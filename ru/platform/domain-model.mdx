Эта страница — единственный источник правды о доменной модели платформы Cevexa. Все репозитории (сайт, API, база данных, боты) и все скилы агентов ссылаются на неё, а не хранят собственные копии этих правил.

## Сервер

**Сервер** — основной объект Cevexa. У каждого сервера есть собственные идентичность (ID, название, описание, иконка), владелец, участники, роли, настройки, интеграции, панель управления и жизненный цикл.

У сервера есть `type`:

| Тип | Значение |
|---|---|
| `server` | Обычный сервер. Может иметь департаменты. |
| `department` | Департамент. Это полноценный независимый серверный объект, а не папка и не подмодуль другого сервера. |

Гильдия Discord — **не** сервер Cevexa. Гильдия — это внешний ресурс, который можно *подключить* к серверу через [интеграцию](#интеграции).

## Департамент

Департамент — это сервер с `type` = `department`. У него есть всё, что есть у обычного сервера: собственные ID, владелец, участники, роли, настройки, интеграции (включая собственную гильдию Discord) и панель управления.

Департамент:

- может существовать сам по себе, без родителя;
- может иметь **не более одного** родителя, и родитель должен быть обычным сервером;
- не может иметь собственных департаментов (без вложенности);
- может быть в любой момент привязан к родителю, переназначен другому родителю или отвязан и остаётся полностью рабочим после отвязки.

## Родительская связь

Связь хранится в департаменте как необязательное поле `parent_server_id`.

| Правило | Где обеспечивается |
|---|---|
| Родитель может быть только у `department` | CHECK в базе + API |
| Родитель должен быть обычным `server` | Триггер в базе + API |
| Сервер не может быть родителем самому себе | CHECK в базе |
| У департамента не может быть департаментов | Триггер в базе + API |
| Удаление родителя никогда не удаляет его департаменты | Внешний ключ `ON DELETE RESTRICT` + API |
| Смена родителя не переносит владельца и участников | API (меняется только связь) |
| Родительский сервер не получает административного доступа к департаменту | Авторизация в API |

Участники родительского сервера видят базовые данные его департаментов (название, иконку, тип, статус интеграций). Другого доступа к департаменту у них нет, если они не являются его участниками.

## Владение и участники

У каждого сервера ровно один **владелец** — пользователь Cevexa, который его создал. Участники хранятся отдельно для каждого сервера, у каждого участника одна роль:

| Роль | Может |
|---|---|
| `owner` | Всё, включая удаление сервера и смену его типа |
| `administrator` | Изменять сервер, управлять интеграциями, создавать, привязывать и отвязывать департаменты |
| `member` | Просматривать сервер, участников и интеграции |

Владение и участие относятся к одному серверу. Они никогда не наследуются от родительского сервера или от гильдии Discord. Установка бота Cevexa в гильдию Discord никого не делает владельцем сервера Cevexa.

## Конвертация

Сервер можно превратить в департамент и обратно. Конвертация меняет `type` **существующего** объекта и никогда не создаёт замену. ID, владелец, участники, настройки и интеграции сохраняются.

- **Сервер → департамент.** Только владелец. Новый департамент можно оставить независимым или сразу привязать к обычному серверу. Если у сервера ещё есть департаменты, конвертация отклоняется (`server_has_departments`), пока их не отвяжут или не перенесут к другому серверу.
- **Департамент → сервер.** Только владелец. Родительская связь удаляется, тип меняется; интеграции и данные сохраняются.

Каждая конвертация выполняется в одной транзакции базы данных.

## Интеграции

**Интеграция** подключает сервер к ресурсу внешней платформы. Сейчас поддерживаются:

| Провайдер | Внешний ресурс | Статус |
|---|---|---|
| `discord` | Гильдия Discord | Доступно |
| `erlc` | Приватный сервер ER:LC | Пока недоступно |

Правила:

- У сервера может быть не более одной интеграции на провайдера.
- Внешний ресурс (например, гильдия Discord) может быть подключён только к одному серверу или департаменту Cevexa одновременно.
- Интеграция Discord у департамента не зависит от интеграции Discord у его родителя.

Статусы интеграции:

| Статус | Значение |
|---|---|
| `active` | Подключение подтверждено, бот Cevexa находится в гильдии |
| `bot_missing` | Гильдия всё ещё подключена, но бота из неё удалили. После повторной установки бота статус снова станет `active` |

Отключение интеграции удаляет её. Сервер никогда не удаляется из-за того, что бот покинул гильдию. Полный жизненный цикл описан в разделе [Интеграция с Discord](/ru/platform/discord-integration).

## Хранение

PostgreSQL (схема `platform`) — основная система хранения серверов, участников, интеграций и ожидающих подключений. Redis хранит только краткоживущие данные (кэш сессий, кэш гильдий OAuth, множества установок бота, дедупликация событий). MongoDB хранит конфигурацию гильдий бота и логи. HTTP-контракт описан в разделе [API серверов](/ru/api/servers).
